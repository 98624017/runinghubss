欢迎使用 **RunningHub API**

:::

**核心优势：**

## 2. 开始使用

### 2.1 准备工作
在发起 API 调用前，请完成以下准备事项：


<Container>
  <Steps>
  <Step title="注册账号">
    访问 https://www.runninghub.cn/ 注册 RunningHub 账号
  </Step>
  <Step title="开通会员">
    开通**基础版及以上会员**（免费用户暂不支持 API 调用）
  </Step>
  <Step title="获取 Workflow ID">
    打开目标工作流页面，从浏览器地址栏获取 ID。
     > 以`https://www.runninghub.cn/#/workflow/1850925505116598274` 为例：
            其中ID 为 `1850925505116598274`
  </Step>
</Steps>
 :::caution[]
    注意：目标工作流必须在网页端**手动成功运行过至少一次**，否则 API 调用将报错。
 :::
</Container>

### 2.2 获取 API KEY

> RunningHub 为每位用户分配唯一的 32 位 API KEY 用于身份验证。
**获取方式**
<Container>
  <Steps>
  <Step title="">

  <Step title="">

  </Step>
  <Step title="">

      <br/>

  </Step>
</Steps>
</Container>



## 3. 账户类型说明
API 调用方式一致，但根据账户类型不同，计费与权益有所区别：

| 类型 | 适用场景 | 计费模式 | 并发支持 |
| :--- | :--- | :--- | :--- |
| **消费级** | 基础会员及以上 | **消耗 RH 币**<br>费率与网页端运行工作流一致 | 默认单任务 |
| **企业级-共享** | 需充值余额 | **按实际运行时间计费**<br>详见网站资费说明 | **支持高并发**<br>默认支持 100 并发 |
| **企业级-独占** | 购买独占机器 | **根据不同机器类型付费**<br>详见网站资费说明 | **并发数同购买机器数量** |

## FAQ 常见问题

<AccordionGroup>
  <Accordion title="API 如何计费？" defaultOpen>
    消费级 API 没有独立计费体系，价格与在网页端运行同一个工作流完全一致，仅通过 API 触发执行。
  </Accordion>
  <Accordion title="如何实现高并发（同时发起多个任务）？">
    请使用**企业级 API Key** 进行调用，默认支持 50 个并发任务。
  </Accordion>
  <Accordion title="如果工作流包含多个 Save 节点，结果如何返回？">
    API 会将所有输出文件打包，通过 response 中的 `data` 字段以数组形式返回。
  </Accordion>
    <Accordion title="图生图 (Img2Img) 场景下如何上传图片？">
    请按以下步骤操作：
1. 调用 `/task/openapi/upload` 接口将图片上传至 RunningHub 服务器。
2. 在工作流参数中通过 `Load Image` 节点引用上传后的路径。
3. 参考实现代码：[GitHub - ComfyUI_RH_APICall](https://github.com/HM-RunningHub/ComfyUI_RH_APICall)
  </Accordion>
    <Accordion title="返回 `APIKEY_INVALID_NODE_INFO` 错误？">
   这表示提交的 `nodeInfoList` 参数与工作流定义不匹配。请逐项检查 JSON 中的 `nodeId`、`fieldName` 和 `fieldValue` 是否正确。
  </Accordion>
    <Accordion title="返回 `APIKEY TASK STATUS ERROR` 错误？">
    API 会将所有输出文件打包，通过 response 中的 `data` 字段以数组形式返回。
  </Accordion>
</AccordionGroup>

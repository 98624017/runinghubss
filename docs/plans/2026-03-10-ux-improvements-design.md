# 悦安居 UX 体验提升设计方案

> 日期：2026-03-10
> 状态：已确认，待实施

## 背景

悦安居 AI 家装出图平台功能框架已完善，但用户体验存在三个核心短板：

1. **任务反馈缺失** — 任务完成无通知，跨应用任务不可见
2. **图片处理能力空白** — 上传即使用，无裁剪/压缩/调色能力
3. **工作流效率低** — 重复操作多，缺少模板/复用/批量机制

目标用户为专业设计师/装修公司（高频、批量、多应用并行）和普通业主（偶尔使用、关注易用性）两类。

## 架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 通知方式 | 纯前端（Notification API + 页面内通知中心） | 零后端改造，快速上线 |
| 图片处理 | 浏览器端（Canvas API + CSS Filters） | 零服务端依赖，隐私安全 |
| 数据持久化 | IndexedDB + localStorage | 与现有方案一致 |
| UI 框架 | 复用 shadcn/ui + Motion | 设计语言统一 |

## 不做的事情（YAGNI）

- 不做服务端推送（WebSocket/SSE）— 轮询机制已足够
- 不做团队协作功能 — 当前是个人工具，需求不明确
- 不做图片 AI 增强（超分辨率等）— 超出工具定位
- 不做复杂的任务编排/工作流 — 保持简单

## 第一阶段：任务反馈体系（P1）

解决核心痛点：用户提交任务后"不知道发生了什么"。

### 1.1 全局任务面板

**用户故事：** 作为用户，我同时在多个应用中提交任务，希望能在一个地方看到所有进行中任务的状态。

**设计：**
- Header 右上角新增"任务"图标按钮，带数字角标显示进行中任务数量
- 点击展开下拉面板，列出所有活跃任务（跨应用）
- 每个任务卡片显示：应用名 | 状态（动画） | 已用时间
- 完成的任务保留 30 秒后淡出，点击可跳转到对应工作区
- 面板底部显示"查看全部历史"链接

**技术要点：**
- 数据源：`useTaskStore.activeTasks`（已有的 Zustand store）
- 组件位置：`src/components/layout/task-panel.tsx`
- 依赖：shadcn/ui Popover + ScrollArea

### 1.2 浏览器桌面通知

**用户故事：** 作为用户，我提交任务后切去其他标签页，任务完成时希望收到桌面通知。

**设计：**
- 任务状态变为 SUCCESS/FAILED 时触发 `Notification API`
- 首次使用时请求权限，在设置页提供开关
- 通知内容包含应用名称 + 结果缩略图（成功时）
- 点击通知自动聚焦到对应任务页面

**技术要点：**
- Hook：在 `useTaskStore` 的 `pollTask` 回调中触发
- 权限管理：`Notification.requestPermission()`
- 设置存储：localStorage `yueanji-notification-settings`

### 1.3 声音提醒

**用户故事：** 作为用户，我希望任务完成时有声音提醒，即使不看屏幕也能知道。

**设计：**
- 内置一个轻柔的提示音（< 50KB）
- 设置页提供开关和音量控制
- 仅在 SUCCESS/FAILED 时播放
- 与桌面通知独立控制

**技术要点：**
- 使用 `Audio` API 播放
- 音频文件放在 `public/sounds/`
- 设置存储：localStorage

### 1.4 进度增强

**用户故事：** 作为用户，我希望看到更精确的任务进度，而不只是"生成中..."。

**设计：**
- 将当前"生成中..."替换为更丰富的进度状态
- 显示已耗时 + 预估剩余时间（基于同类任务历史平均时长）
- 进度条动画（阶段性提示，即使没有精确百分比）
- 超过平均时长时显示"比平时耗时更长"提醒

**技术要点：**
- 平均时长统计：从 IndexedDB `taskHistory` 按 appId 聚合
- 进度条：shadcn/ui Progress + Motion 动画
- 阶段映射：QUEUED → "排队中" | RUNNING < avg → "生成中（预计还需 Xs）" | RUNNING > avg → "比平时耗时更长"

### 1.5 跨应用任务状态角标

**用户故事：** 作为用户，我在应用A工作时想快速知道应用B的任务完成了没有。

**设计：**
- 侧边栏应用图标上显示状态点：绿色=有完成的、橙色=进行中、红色=有失败的
- Header 导航的"工作台"图标也显示全局状态角标

**技术要点：**
- 数据源：`useTaskStore.activeTasks` 按 appId 分组
- 组件：在 Sidebar 和 Header 中注入角标 Badge

## 第二阶段：图片处理工具链（P2）

解决痛点：上传图片不够灵活，无法预处理。

### 2.1 图片编辑器（弹窗式）

**用户故事：** 作为用户，我上传的照片需要裁剪/调整后再提交 AI 处理。

**设计：**
- 上传图片后，缩略图上浮现"编辑"按钮（画笔图标）
- 点击打开大尺寸模态框，包含工具栏

**编辑器布局：**
```
┌─────────────────────────────────────────────┐
│  裁剪  │  调整  │  调色              [重置] │  ← 工具 Tab
├─────────────────────────────────────────────┤
│                                             │
│              实时预览画布                     │
│                                             │
├─────────────────────────────────────────────┤
│           参数控制区（随 Tab 切换）            │
├─────────────────────────────────────────────┤
│                    [取消]  [应用]             │
└─────────────────────────────────────────────┘
```

**组件位置：** `src/components/workspace/image-editor/`

### 2.2 裁剪工具

**功能：**
- 自由裁剪 + 预设比例（1:1、4:3、16:9、3:4、自定义）
- 可拖拽裁剪框，支持缩放和旋转（90度步进）
- 家装场景特别实用：去掉照片边缘多余部分

**技术方案：** `react-image-crop` 或 Canvas API 纯前端实现

### 2.3 尺寸调整

**功能：**
- 检测上传图片尺寸，超过阈值（如 2048px 长边）自动提示
- 提示："图片尺寸较大（4000x3000），建议缩小以加快处理速度"
- 一键按钮：缩至 2048px / 1536px / 1024px（保持比例）
- 显示预估文件大小变化

**技术方案：** Canvas `drawImage` + `toBlob`

### 2.4 格式压缩（WebP 转换）

**功能：**
- 提供开关："上传时自动转为 WebP（质量 0.95）"
- 可在设置页全局设置默认行为
- 转换在浏览器端完成（`Canvas.toBlob('image/webp', 0.95)`）
- 显示压缩前后文件大小对比

### 2.5 基础调色

**功能：**
- 4 个滑块：亮度、对比度、饱和度、色温
- 实时预览（CSS filter 实现预览，最终 Canvas 输出）
- "自动优化"按钮：一键调整到均衡值
- 预设滤镜：原图、明亮、暖色、冷色

**技术方案：**
- 预览：CSS `filter: brightness() contrast() saturate()`
- 输出：Canvas 2D context + filter 属性
- 色温：通过 sepia + hue-rotate 组合实现

### 2.6 交互流程

```
上传图片 → 缩略图显示 [编辑] 按钮
              ↓ 点击
         图片编辑弹窗
         ├── 顶部：工具切换 Tab（裁剪 | 调整 | 调色）
         ├── 中间：实时预览画布
         ├── 底部：参数控制区
         └── 操作栏：重置 | 取消 | 应用
              ↓ 应用
         替换原缩略图，更新数据
```

**关键原则：**
- 全部浏览器端处理，零服务端依赖
- 编辑是可选的，不影响直接上传流程
- 单图和多图模式都支持编辑按钮
- 编辑结果覆盖原图，保持简单

## 第三阶段：工作流效率提升（P3）

解决痛点：重复操作多，专业用户效率低。

### 3.1 参数模板系统

**用户故事：** 作为设计师，同类户型我经常用相同参数，想保存为模板下次直接用。

**设计：**
- 表单底部新增"保存为模板"按钮
- 模板包含：所有字段值（不含图片）+ 模板名称
- 存储在 IndexedDB（按 apiKeyHash 隔离）
- 工作区顶部新增"模板"下拉，可快速加载
- 支持管理：重命名、删除、导出（JSON）

**数据结构：**
```typescript
interface Template {
  id: string
  name: string
  appId: string
  apiKeyHash: string
  values: Record<string, unknown> // 不含 IMAGE 类型字段
  createdAt: Date
  updatedAt: Date
}
```

### 3.2 历史快速复用

**用户故事：** 作为用户，看到历史记录里某个效果很好，想一键复用它的参数。

**设计：**
- 历史详情弹窗中新增"复用此参数"按钮
- 点击后自动导航到对应应用工作区，预填所有参数
- 图片参数显示提示："需要重新上传图片"

### 3.3 批量任务提交

**用户故事：** 作为用户，有 10 张图要用同样参数处理，想批量提交。

**设计：**
- 新增"批量模式"开关
- 开启后图片上传区变为批量区：上传 N 张图，每张独立生成一个任务
- 共享相同的其他参数（风格、分辨率等）
- 显示队列预览："即将提交 10 个任务，预估总耗时 ~15 分钟"
- 提交后全部进入任务队列，全局任务面板可追踪

### 3.4 失败一键重试

**用户故事：** 作为用户，任务失败了想一键重试而不用重新填表。

**设计：**
- 任务失败时结果面板显示"重试"按钮
- 自动使用上次完全相同的参数重新提交
- 历史记录中的失败任务也支持重试

### 3.5 表单自动保存（草稿）

**用户故事：** 作为用户，切换应用时希望表单能记住上次输入。

**设计：**
- 每个应用独立保存最近一次填写的表单值
- 存储在 localStorage（轻量，按 appId 隔离）
- 进入应用时自动恢复草稿，顶部提示"已恢复上次编辑"
- 提交成功后清除草稿

### 3.6 首次使用引导

**用户故事：** 作为新用户，第一次进入不知道每个参数是干什么的。

**设计：**
- 新用户首次进入时显示简短功能引导（3-4 步 tooltip）
- 步骤：选择应用 → 填写参数 → 上传图片 → 查看结果
- "不再提示"选项，记录到 localStorage

### 3.7 结果对比视图

**用户故事：** 作为用户，想快速对比不同参数下的生成效果。

**设计：**
- 结果面板增加"对比"模式
- 左右滑动对比：原图 vs 生成结果
- 支持从历史记录选择多个结果并排对比
- 复用已有的 `before-after-slider` 组件
